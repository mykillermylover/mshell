# Дизайн: универсальный магнит на контактах

> **Историческая запись.** Актуальный код — источник истины; документ не поддерживается.

Дата: 2026-10-20
Статус: на ревью

## 1. Контекст

Сейчас `../../../src/lib` перебирает кандидатов по каждой оси: стены рамки
и ближнюю сторону каждого соседа (сторона выбирается по центру окна).
Из пар `x × y` выбирается вариант с большим числом прилипших сторон,
затем с меньшей суммой зазоров. Свободная ось дополнительно клампится
у скруглённого угла.

Следствия:

- зона притяжения квадратная (по каждой оси отдельно), поэтому у угла
  возможен диагональный сдвиг до `waistReach·√2` (62 px при 44);
- нет проверки третьего тела — окно можно посадить поверх другого;
- выбор стороны по центру и кламп свободной оси — отдельные ветки;
- цель у угла рамки — квадратный внутренний угол, а не дуга.

Жидкость уже описывает соединения через `Contact` (`geometry.ts`): ближайшие
точки, зазор, нормаль. Магнит должен использовать ту же геометрию, чтобы
«мостик появился → окно прилипло» было одним правилом.

## 2. Цель

Один универсальный механизм: притягивание и выпихивание — это закрытие
контактов. Никаких отдельных веток «стена / бок / угол / дуга».

## 3. Модель

### 3.1 Контакты

- окно ↔ рамка — `contactsWithFrame(self, frame)`: 4 прямых участка стен
  и 4 дуги внутренних углов;
- окно ↔ другое тело — `contactBetween(self, other)`;
- Pop — такое же тело, как Float; скрытые тела не участвуют;
- у контакта есть `gap`, нормаль `n` (a → b), точки `a` и `b`.

### 3.1.1 Общее с жидкостью

Жидкость и магнит используют один и тот же `geometry.ts` для ближайших
соседей: тот же набор контактов, те же `gap`, нормали и точки. Это
единственная общая часть.

- Жидкость рисует мостик для каждого подходящего контакта сразу; выбора
  между контактами, пар и проверки коллизий у неё нет. Закон ширины
  мостика — её собственный.
- Магнит фильтрует контакты по `waistReach`, строит одиночные и парные
  сдвиги, проверяет остаток/коллизии и выбирает один вариант.

Если брейншторм жидкости изменит `Contact` или `geometry.ts`, магнит и
мостики нужно обновлять вместе — иначе они разъедутся.

### 3.2 Кандидаты

- положительный контакт: `0 <= gap <= waistReach` — мостик уже появился;
- отрицательный: `gap < 0` — пересечение, это выпихивание;
- одиночный кандидат: сдвиг `t = n * gap` (для отрицательного — наружу);
- пара контактов: если нормали не параллельны (детерминант > ε),
  решается система `n₁·t = gap₁`, `n₂·t = gap₂`;
- тройки не рассматриваются: обычно система переопределена, выигрыш
  сомнительный;
- пара с почти параллельными нормалями отбрасывается.

### 3.3 Проверка кандидата

1. Применить `t` к позиции окна (`Body`).
2. Пересчитать выбранные контакты: пара решается линейно по текущим
   нормалям, поэтому требуется `|gap| <= 0.5` для каждого выбранного
   контакта; иначе кандидат отбрасывается.
3. Пересечения: для каждого другого тела
   `contactBetween(moved, other).gap >= -ε`; для рамки все 8 контактов
   `gap >= -ε` (окно не залезает в материал рамки). Проверка идёт по
   скруглённым телам, не по прямоугольникам.
4. Цель в координатах поля; `Frame.moveTo` по-прежнему клампит твин в
   экран.

### 3.4 Выбор

Если при отпускании есть хотя бы один отрицательный контакт:

1. рассматриваются только кандидаты, снимающие пересечения;
2. среди них — больше снятых отрицательных контактов;
3. затем — меньше `|t|`;
4. затем детерминированный tie-break;
5. если валидного нет — окно остаётся как отпустили.

Глубокое перекрытие, когда `contactBetween` вернул `null` (ядра
пересеклись, контактной нормали нет): fallback — вытолкнуть по оси
минимального перекрытия bounding box на величину перекрытия + 0.5 px,
затем снова проверить все коллизии; если валидного варианта нет —
остаёмся.

Иначе — притягивание:

1. больше закрытых положительных контактов (после проверки);
2. меньше `|t|`;
3. детерминированный tie-break.

Tie-break не зависит от порядка тел: сравниваются отсортированные
координаты точек контактов. Это защищает от мигания при равных вариантах.

### 3.5 Триггер

- Один параметр `waistReach` для мостика и магнита.
- `gap == waistReach` включается, `gap > waistReach` — нет.
- Видимая жидкость после blur и порога появляется позже; это принято:
  при отпускании окно уже прилипло, размазанная часть не бросается в глаза.
- Отдельного `snapReach` нет.

## 4. Длительности

Две настройки в `style`:

| Ключ | Дефолт | Что делает |
|---|---:|---|
| `snapDuration` | 340 мс | твин магнита и выпихивания |
| `revealDuration` | 400 мс | выезд/скрытие Pop и Float |

- Оба входят в `FieldStyle`, `DEFAULTS` и `LIMITS`; диапазон 0–2000 мс.
- Текущие Pop 420 и Float 380 заменяются общим дефолтом 400 — это осознанное
  небольшое изменение скорости.
- Значения живые: изменение через конфиг применяется без перезапуска.
- `PopSpec.duration` удаляется — второго источника длительности нет.
- `Pop.apply()` дополнительно выставляет `transitionDuration`;
  `Float` получает `apply()`/геттер и обновляется из `Frame.refresh()`
  вместе с Pop.
- `Frame.snapFloat` берёт `this.style.snapDuration()`.

## 5. Интерфейсы

```
snapTo(
  env: { frame: FrameSpec; reach: number },
  self: Body,
  others: Body[],
): { x: number; y: number } | null
```

- `Body` и `FrameSpec` — из `../../../src/lib`; `cornerRadius` у
  self/others равен `windowRadius`.
- `Frame.snapTarget` собирает `Body` для себя и видимых соседей по
  фактическим границам и `windowRadius`.
- `snap.ts` остаётся чистым (без GJS) и тестируется в node.
- `Frame.refresh()` применяет длительности к Pop и Float.

## 6. Тесты

`tests/snap.test.ts` переписывается под новую модель. Обязательные случаи:

- стена: окно в нескольких px — вплотную к внутренней кромке;
- бок: окно рядом с другим — в стык стороной;
- диагональ окно↔окно: касание скруглёнными уголками;
- угол рамки: две стены закрываются парой, окно не залезает в материал
  рамки (дуга участвует в контактах и проверке, но паре стен обычно
  проигрывает по длине сдвига);
- третий контакт/третье тело: кандидат с пересечением отбрасывается;
- выпихивание: перекрытие снимается по нормали, результат без пересечений;
- граница: `gap == reach` притягивает, `gap > reach` — нет;
- независимость от порядка тел и симметрия четырёх стен;
- `windowRadius < screenRadius`: угол не перекрывает рамку.

Конфиг:

- `snapDuration` и `revealDuration` есть в дефолтах и лимитах;
- `LIMITS` покрывает все ключи `style`;
- значения зажимаются (общий тест `reactive` с лимитами).

Автотестов на GTK-твин/реальное окно нет — только живой прогон.
CPU-модель жидкости не меняется.

## 7. Принятые компромиссы

- Угол рамки закрывает две стены: возможен диагональный сдвиг до 62 px
  при `waistReach = 44`. Это следствие правила «больше контактов»,
  принято.
- Диагональный подлёт к другому окну даёт касание уголками, а не
  прижатие стороной. Если понадобится стык сторон, добавим предпочтение
  стороны для контактов с `seam > 0` — это отдельное небольшое правило.
- Пара решается линейно; при остатке > 0.5 px отбрасывается.
- Глубокое перекрытие (`contactBetween === null`) выпихивается по оси
  bounding box, а не по нормали: нормали в этом случае нет.
- Если валидного кандидата при выпихивании нет, окно остаётся на месте.
- Во время drag магнита и коллизий нет — только на отпускании.

## 8. Вне рамок

- тройные и более контакты;
- коллизии во время перетаскивания;
- изменения жидкости/мостиков (отдельный брейншторм);
- распил `Frame` (после магнита);
- наблюдение за файлом конфига (правка руками требует перезапуска).

## 9. Критерии приёмки

- Все новые unit-тесты зелёные; eslint и tsc без новых ошибок в файлах
  репозитория (ошибки AGS/gnim из nix-store не в счёт).
- Магнит не создаёт новых пересечений; существующие снимает, если есть
  валидный кандидат.
- Смена `snapDuration`/`revealDuration` через конфиг применяется живьём.
- Живой прогон: стены, диагональ, угол рамки, ниша, перекрытие, Pop.
